# STRIPSLab method and prior work

## What this implements

An original bounded educational implementation of established positive propositional STRIPS semantics, exact finite shortest paths and delete-relaxation heuristics. No new algorithm is claimed. No external planner code, examples, dataset or benchmark results were copied. Python uses integer state masks, reverse multi-source BFS and exact integer counting. JavaScript constructs successors with sets, computes all-state distances through repeated Bellman sweeps and counts with BigInt. Both export ordinary JSON, with every plan count stored as a decimal string.

Input has exactly `facts`, `initial`, `goal`, `actions`. There are 0..6 facts and 0..8 grounded actions. Initial and goal are arrays of distinct valid fact indices. Each action has exactly `pre`, `add`, `delete`, also distinct-index arrays. Add and delete must be disjoint. Preconditions may overlap effects. Action position is its identity; duplicate action definitions are allowed and remain distinct choices. Input fact lists are canonicalized into ascending order, while action order is preserved. Every action costs one, including a no-op.

This is not a PDDL parser or grounding system. There are no negative preconditions/goals, derived predicates, conditional effects, weighted costs, partial observability, exogenous changes, nondeterminism, concurrency, durative actions or execution. Absence means false, not unknown. Every state is a fully known subset of the supplied facts, including states that may not be reachable from the initial state. The model supplies no additional domain invariants.

## State transitions

An action a is applicable in state s iff pre(a) is a subset of s. Its real successor is `(s minus delete(a)) union add(a)`. Facts not in either effect set are unchanged. Every action is retained for every state, including blocked actions with all missing preconditions and null successors. Applicable actions retain real and relaxed successors plus the facts actually added and actually removed, not just their declared effects.

A state satisfies the goal iff it contains every goal fact. Empty goals are satisfied by every state. Zero facts means one empty state. Goal states terminate a shortest plan immediately; the empty action sequence is the unique zero-length shortest plan, even when actions can leave and later re-enter the goal.

Reachability and distance from the initial state are separate from remaining goal distance. A state can be unreachable from the initial state yet have a finite suffix plan. A reachable state can be a dead end with no goal path. These are different properties and both are shown.

## Exact shortest-plan families

The real and delete-relaxed graphs contain all 2^m states and all applicable action-labelled edges, including self loops. Python runs reverse multi-source BFS from all goal states. JavaScript instead repeatedly sweeps the Bellman recurrence from zero at goal states and infinity elsewhere. Null in JSON represents no finite path, never zero. Unit positive cost implies every shortest suffix edge decreases remaining distance by one. All such action/target pairs are retained, giving an acyclic representation of every shortest suffix sequence without enumerating exponentially many sequences.

The plan count at a goal is one. Else it is the sum of successor plan counts over every shortest action-labelled edge. An unreachable goal distance has count zero and null representative. Duplicate actions count separately; no-ops and cycles cannot enter a shortest plan. The representative always chooses the lowest-index available shortest action at each step. It is one deterministic representative, not the only plan. Plan counts are exact unbounded integers serialized as decimal strings in both engines.

The initial optimal-plan DAG retains every edge `(s,a,t)` satisfying `distance(initial,s) + 1 + distance(t,goal) = optimal(initial,goal)`, with both distances finite. It includes every edge on every initial shortest plan, not every applicable edge. The full report separately retains all edges through all state/action records. No initial optimum means an empty optimal-edge list, not an empty successful plan.

## Delete relaxation and h-plus

The relaxed successor is `s union add(a)` for applicable actions. Deletes are ignored; preconditions and goals are unchanged. `h-plus` is the exact remaining shortest distance in this full relaxed graph. It is not a greedy relaxed-plan estimate and is not h-max or h-add. The relaxed graph and its entire shortest suffix family are audited for each state, just like the real graph.

In this positive fragment, a relaxed state reached by any real action sequence contains the corresponding real state. Hence real solutions remain relaxed solutions and h-plus is a lower bound on h-star. This does not make finite h-plus a solvability certificate. The consumable-resource control has finite relaxed distance two and no real goal path. The initial resource can make either goal but is deleted before the other can be made. Adding a restoration action makes the real optimum three while the relaxed optimum stays two.

## h-max and h-add

For a selected source state s, fact cost is initialized to zero for present facts and infinity otherwise. A synchronous round uses only preceding-round costs. For each action with all finite prerequisite costs, its candidate cost is `1 + aggregate(cost(preconditions))`, where aggregate is maximum for h-max and sum for h-add. An empty prerequisite set aggregates to zero. Each add fact takes the minimum of its old cost and all action candidate costs. Iterate until unchanged, retaining round zero and the final unchanged round. With finitely many facts, positive unit costs and no negative conditions, this converges to the ordinary relaxed fact-cost fixed point. Each estimate is the same aggregate over goal-fact costs, with empty goals zero and any infinite goal cost infinite.

The report retains every fact cost and every tied final best action achiever. Present facts have cost zero and no action achievers; unreachable facts have null cost and no achievers. Local achiever lists are not by themselves a complete jointly consistent plan. Exact relaxed plan choices are separately retained in the relaxed state graph.

For this fragment, `h-max <= h-plus <= h-star` when h-star is finite. h-add can exceed the real optimum because effects or prerequisite work shared across goals are counted more than once. The original one-action/two-goal control has h-star = h-plus = h-max = 1 and h-add = 2. Conversely independent goals expose h-max = 1 with exact relaxed/real optimum 2. Null h-max, h-add and h-plus coincide on relaxed dead ends; real dead ends can still have finite estimates. No heuristic-search speedup, A* implementation, practical planner benchmark or real-world safety claim is made.

## Validation and references

The native reference constructs state successors with sets, computes all-pairs distances via Floyd-Warshall, and counts all bounded walks at each exact shortest length. It independently replays representative plans, checks every shortest suffix choice and every initial optimal edge, and verifies actual changed facts. A recursive bounded-height derivation-tree oracle computes h-max/h-add fact costs, separate from the fixed-point update code. Every retained round and all tied achievers are checked. Generic inequalities and infinity conventions are checked on every state.

Native tests cover all 28 zero-or-one-action single-fact tasks, 100 seeded tasks with 0..3 facts and up to four actions, and all 14 retained tasks, including a six-fact chain. JavaScript compares full reports for 24 single-action single-fact tasks, a different 100 seeded tasks with 0..4 facts and up to five actions, and the 14 retained controls. These seeded suites are distinct; no claim of identical random tasks is made. The references and task generator are deterministic. Coverage counts describe tests, not benchmark accuracy or speed.

The retained controls cover 127 states, 524 state/action checks, 36 initial optimal-plan edges, 50 initially reachable states and 866 heuristic fixed-point round vectors. Browser tests inspect every retained report, selected state, transition, real/relaxed plan replay, suffix choice, goal estimate, fact-cost round, achiever and export. Invalid edits immediately hide and clear the old audit and disable export. Every retained task is layout-checked at 320/390/1280.

Native JSON input is limited to 65,536 UTF-8 bytes, rejects duplicate keys, nonfinite constants, booleans and non-integer numeric schema fields, validates before writing, and atomically replaces an output path only after success. Browser JSON.parse uses a 65,536-character limit, accepts integral JavaScript numbers such as 1.0, and retains the last duplicate key as JSON.parse does. These parser differences are deliberate and disclosed, not claimed as cross-interface equivalence on malformed input. The strict CLI rejects invalid UTF-8. Installed-wheel checks run outside the checkout, compare all 14 complete reports, verify three installed module origins and both CLI entry points.

## Inspected prior sources and scope

1. David Poole and Alan Mackworth, *Artificial Intelligence: Foundations of Computational Agents*, 2nd edition, section 6.1.2, STRIPS action representation, preconditions/effects and unchanged-feature assumption. This text also presents richer signed feature assignments and derived features, neither implemented here. https://artint.info/2e/html2e/ArtInt2e.Ch6.S1.SS2.html
2. Blai Bonet and Hector Geffner, *Planning as heuristic search*, Artificial Intelligence 129 (2001), sections 2-4. Positive grounded unit-cost STRIPS state model, ignored-delete relaxation, fact-cost fixed points, h-add nonadmissibility and h-max admissibility. Sections 2-4 were directly inspected; paper performance results and HSP search code are not reproduced or claimed. https://cs.uky.edu/~sgware/reading/papers/bonet2001planning.pdf
3. Patrik Haslum and Hector Geffner, *Admissible Heuristics for Optimal Planning*, AIPS 2000. Inspected abstract, background and introduction of the heuristic family. Distinguishes admissible heuristic from optimal search and relates h-max to singleton subgoal estimates. The broader h-m family, regression and IDA* planner are not implemented. Extracted PDF text has degraded notation, so exact implemented equations are grounded primarily in source 2 and source 6. https://www.ida.liu.se/divisions/aiics/publications/AIPS-2000-Admissible-Heuristics-Optimal.pdf
4. Pyperplan official documentation and README. Existing lightweight positive STRIPS planner, PDDL parsing/grounding, BFS and heuristic search; teaching/prototyping positioning and unit-cost fragment. Existing software, not a dependency or an affiliation. No GPL code or benchmark examples are reused. https://github.com/aibasel/pyperplan/blob/main/doc/documentation.md and https://github.com/aibasel/pyperplan
5. Fast Downward official evaluator documentation, definitions and Additive/Max sections. Admissibility, consistency and safe dead-end detection are different properties; additive is not admissible, while h-max is admissible/consistent without axioms. Fast Downward supports language features this project does not. Only the named sections were needed and inspected; no Fast Downward code is reused. https://www.fast-downward.org/latest/documentation/search/Evaluator/
6. Alvaro Torralba and Cosmina Croitoru, *AI Planning, Chapter 9: Delete Relaxation Heuristics*, Saarland winter 2018/2019, slides crediting Jorg Hoffmann. Inspected introduction, delete-relaxation definition, h-plus and h-add/h-max property sections. Supports exact h-plus versus approximate fact estimates, lower-bound and dead-end distinctions. No slide examples are copied. https://fai.cs.uni-saarland.de/teaching/winter18-19/planning-material/planning09-delete-relaxation-heuristics-post-handout-4up.pdf
7. University of Wisconsin CS 540 lecture notes, Planning, initial problem/assumptions section. Deterministic sequential complete-state planning, closed-world convention and goal conjunctions. Its broader situation-calculus discussion is outside scope. https://pages.cs.wisc.edu/~dyer/cs540/notes/planning.html

Sources span primary planning papers, teaching texts/lecture materials and existing software documentation. This is an audit/teaching interface with original synthetic controls, not a replacement for these planners or a research novelty claim.
